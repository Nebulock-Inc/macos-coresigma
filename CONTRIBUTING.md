# Contributing to coreSigma

Thank you for your interest in contributing! This document describes how the repository is laid out and what a change needs before it can merge.

## Project Structure

```
macos-coresigma/
├── rules/
│   ├── esf/                       # Sigma rules on Endpoint Security events
│   ├── ul/                        # Sigma rules on Unified Log lines
│   └── correlation/               # Sigma correlation rules
├── pipelines/pysigma-pipeline-macos/
│   ├── sigma/pipelines/macos/     # the plugin; taxonomy.py is the single source of categories and fields
│   └── tests/                     # plugin tests
├── collectors/                    # esf_collector.py, ul_collector.py, outputs.py, auth.py
├── scripts/                       # deploy, bench, replay, support matrix
├── filters/examples/              # Sigma filters for tuning
├── simulations/                   # atomic simulations and run_sim.sh
├── splunk/coresigma_app/          # generated by deploy_sigma_rules.py --target splunk
├── tests/                         # repository tests (rules, collectors, scripts)
└── docs/                          # documentation; SUPPORT_MATRIX.md is generated
```

## How to Contribute

### Reporting Issues

1. Check if the issue already exists
2. Create a new issue with:
   - Clear description of the problem
   - Steps to reproduce
   - Expected vs actual behavior
   - System information (macOS version, Python version, backend and its version)

### Contributing Code

1. Fork the repository
2. Create a feature branch: `git checkout -b feature/my-feature`
3. Make your changes
4. Add tests if applicable
5. Ensure all tests pass: `pytest -q`
6. Commit with clear messages
7. Push and create a pull request

### Adding New Rules

1. Put ESF rules in `rules/esf/`, Unified Log rules in `rules/ul/`, correlations in `rules/correlation/`.
2. Logsource: `product: macos` and a `category` from the taxonomy (`taxonomy.py`; [docs/FIELD_NAME_ORIGINS.md](docs/FIELD_NAME_ORIGINS.md) lists them). UL rules also need `service: unifiedlog`. Never put ESF event numbers or `event.action` in a rule: the category scopes it.
3. Use only the taxonomy's Sigma field names; the pipelines fail a rule with any other field.
4. Give it a fresh random UUID (`python3 -c "import uuid; print(uuid.uuid4())"`), `YYYY-MM-DD` dates, a `level`, and `falsepositives`.
5. Tag ATT&CK techniques and tactics in the hyphenated form that pySigma's bundled ATT&CK data accepts (`attack.stealth`, `attack.defense-impairment`, `attack.t1059.002`).
6. Check that it converts: `sigma convert -t splunk -p macos_esf_ecs -p macos_ul_ecs <rule>` (a correlation from a directory with its base rules; see [docs/SIGMA_TOOLS_USAGE.md](docs/SIGMA_TOOLS_USAGE.md#correlations)).
7. Regenerate the Splunk app: `python3 scripts/deploy_sigma_rules.py --target splunk`.

`tests/test_rules_lint.py` checks the IDs, dates, logsource, tags, level and false positives. Don't set `custom.coresigma.status` or verdicts by hand, and don't edit `docs/SUPPORT_MATRIX.md`: `scripts/rule_matrix.py` writes both from measured runs.

For maintainers: `scripts/sample_private_baseline.py --log FILE` (`--log` is required) measures ESF rule noise on a laptop's own eslogger log for `rule_matrix.py verdicts --noise`; it writes only under its private directory (`--out`, default `~/.coresigma/private`, outside any git checkout), sends only to an Elasticsearch on the same machine, and its numbers never go into the repository.

### Improving the Plugin

1. Categories and fields live in `pipelines/pysigma-pipeline-macos/sigma/pipelines/macos/taxonomy.py`. The collectors read the same table, so a change there changes what they collect and how their documents look.
2. Test with the plugin's suite (`pipelines/pysigma-pipeline-macos/tests/`) and the repository's (`tests/`).
3. Document new categories and fields in [docs/FIELD_NAME_ORIGINS.md](docs/FIELD_NAME_ORIGINS.md).

## Code Style

- Python: Follow PEP 8. The collectors use only the standard library and must run on the stock macOS `python3` (3.9).
- YAML: Use 2-space indentation
- Comments: Explain complex logic
- Docstrings: Use for all functions/classes

## Testing

Run tests before submitting:

```bash
pytest -q                    # repository and plugin tests (pytest.ini deselects the bench tests)
                             # ClickHouse tests skip unless requirements-clickhouse.txt is installed (Python 3.13+)
pytest -q -m bench           # needs the Docker bench (./scripts/bench_up.sh elastic splunk opensearch clickhouse)
                             # and requirements-clickhouse.txt
```
