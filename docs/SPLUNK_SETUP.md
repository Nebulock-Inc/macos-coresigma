# Splunk Setup

## Splunk Free License

The bench stack uses Splunk Free license, which has the following limitations:

### Verified Limits

**Date verified:** 2026-11-10  
**Splunk version:** 9.4.17  
**License type:** Free

Verified via REST API (`/services/licenser/licenses` and `/services/licenser/groups`):

- **Daily indexing limit:** 500 MB/day (524,288,000 bytes)
- **License status:** VALID
- **Active license group:** Free (is_active=1)
- **Free mode confirmed:** isFree=1

### Features Disabled in Free License

Splunk Free has the following limitations compared to Enterprise:

- **Alerting:** Disabled (cannot create scheduled alerts or real-time alerts)
- **Forwarding:** Disabled (cannot forward data to other Splunk instances; isForwarding=0)
- **User authentication:** Limited (only admin user, no LDAP/SAML integration)
- **Distributed search:** Not available (cannot search across multiple Splunk instances)
- **Scheduled searches:** Disabled (no scheduled reports or dashboards)
- **Role-based access control:** Not available

### Data Input Configuration

The bench stack is pre-configured with:

- **HEC (HTTP Event Collector):**
  - Enabled on port 8088 (exposed as 127.0.0.1:8088)
  - Token: Auto-generated by `scripts/bench_up.sh` and stored in `.env` as `SPLUNK_HEC_TOKEN`
  - Default index: `macos`
  - A rerun of `bench_up.sh splunk` reuses the existing `coresigma-bench` token and writes it to `.env` again

- **Index:**
  - Name: `macos`
  - Type: event
  - Auto-created by `scripts/bench_up.sh`

### Accessing Splunk

- **Web UI:** http://127.0.0.1:8000
- **Management API:** https://localhost:8089 (not exposed outside container, use `docker exec`)
- **Username:** admin
- **Password:** Set in `.env` as `SPLUNK_PASSWORD` (default: changeme)

### Verification Steps

To verify Splunk Free license from the REST API:

1. Start Splunk: `./scripts/bench_up.sh splunk`
2. Check license details:
```bash
docker exec splunk curl -s -k -u admin:changeme \
  https://localhost:8089/services/licenser/licenses | \
  grep -E "<s:key name=\"(label|quota|status|type)\">"
```

Expected output should include:
- `<s:key name="label">Splunk Free</s:key>`
- `<s:key name="quota">524288000</s:key>` (500 MB)
- `<s:key name="status">VALID</s:key>`
- `<s:key name="type">free</s:key>`

3. Verify Free mode is active:
```bash
docker exec splunk curl -s -k -u admin:changeme \
  https://localhost:8089/services/server/info/server-info | \
  grep -E "<s:key name=\"isFree\">"
```

Expected: `<s:key name="isFree">1</s:key>`

### Notes

- The Splunk container runs under emulation (linux/amd64 on arm64 Mac)
- First startup is slow (5-10 minutes) due to Ansible playbook execution
- Management port 8089 is not exposed in docker-compose.yml (access via docker exec)
- Web UI port 8000 is exposed as 127.0.0.1:8000
- HEC port 8088 is exposed as 127.0.0.1:8088
- Data indexed counts toward the 500 MB/day limit
- The container automatically activates the Free license on first startup

## The coreSigma App

`scripts/deploy_sigma_rules.py --target splunk` converts every rule, correlations included, and writes the app `splunk/coresigma_app`: one saved search per rule (`coreSigma: <rule title>`, on `index=macos`) and a `coreSigma overview` dashboard. The searches are disabled because Splunk Free has no scheduled searches or alerting; run them from **Search & Reporting → Searches, reports, and alerts**. On a licensed Splunk, enable them (each has a 5-minute `cron_schedule`) and add alert actions.

To install it, copy the app into `$SPLUNK_HOME/etc/apps/` and restart Splunk. On the bench:

```bash
python3 scripts/deploy_sigma_rules.py --target splunk
docker cp splunk/coresigma_app splunk:/opt/splunk/etc/apps/
docker restart splunk
```

The bench keeps only `/opt/splunk/var` in a volume, so copy the app again after the container is recreated.

Correlation searches count in fixed `bin` windows of the correlation's timespan, so a chain that crosses a window boundary is missed. The two ordered correlations run as their declared unordered fallback (`custom.coresigma.splunk: temporal`).

## Sending Collector Data to Splunk

Both collectors send to HEC with `--output splunk`; the token comes from `SPLUNK_HEC_TOKEN`, and `--insecure` accepts the bench's self-signed certificate:

```bash
export SPLUNK_HEC_TOKEN="$(grep '^SPLUNK_HEC_TOKEN=' .env | cut -d= -f2-)"
python3 collectors/ul_collector.py --output splunk --hec-url https://localhost:8088 --insecure
sudo --preserve-env=SPLUNK_HEC_TOKEN python3 collectors/esf_collector.py --output splunk --hec-url https://localhost:8088 --insecure
```

Documents go to index `macos` with sourcetype `coresigma:esf` or `coresigma:ul`. HEC can't deduplicate, so a batch whose reply was lost and was sent again is indexed twice.
